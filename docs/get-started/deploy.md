# Deploy with Docker

WealthPilot runs as a set of containers managed by Docker Compose. One command builds and starts the whole stack: the console, the tool servers, the database, the embeddings service and the tracking server.

## Requirements

| Requirement | Detail |
|---|---|
| Docker Engine with the Compose plugin | Docker 24 or later |
| Memory | about 4 GB available to Docker |
| Disk | about 6 GB for images and volumes |
| Internet access | at first start (image downloads, the embedding model, the sanctions list) and at run time (the hosted model service) |
| A model API key | an NVIDIA NIM key from build.nvidia.com; the free tier works but is slow |

## Start

```bash
git clone <repository-url> wealthpilot && cd wealthpilot
export NVIDIA_API_KEY=<your key>        # or NVIDIA_NIM_API_KEY; or put it in a .env file next to docker-compose.yml
docker compose up -d --build
```

The first start takes several minutes: images are built or downloaded, the embedding model is pulled, the sanctions list is downloaded and the credit policies are indexed. Watch progress with
`docker compose logs -f`. When `docker compose ps` shows every service healthy, open **http://127.0.0.1:8501**.

Check the installation:

```bash
docker compose exec console wealthpilot doctor
```

Then continue with [Your first case](first-case.md).

## What runs

| Service | Role | Port |
|---|---|---|
| `console` | The web console | 8501, published on `127.0.0.1` |
| `mcp` | The three tool servers: calculations and risk scoring (8101), policy search (8102), borrower research (8103) | internal |
| `postgres` | Database with the vector extension: cases, memory, policy vectors, cache, audit log | 5432, published on `127.0.0.1` |
| `ollama` | Local embeddings service for policy search | internal |
| `mlflow` | Tracking server: one trace per case | internal |
| `ollama-pull` | One-shot job that downloads the embedding model | none |
| `bootstrap` | One-shot job that creates data folders and downloads the sanctions list | none |

Start-up order is enforced with health checks: the tool servers wait for the database, the embedding model and the bootstrap job; the console waits for the tool servers.

Data is kept in named volumes: `pgdata` (database), `ollama` (embedding model), `data` (uploaded documents, sanctions list, demonstration data) and `mlflow` (traces). They survive `docker compose down`.

The console has no login. The default deployment publishes it on the loopback address only; read [Security and access](../administration/security.md) before exposing it.

## Configure

Set variables in the shell or in a `.env` file beside `docker-compose.yml`. The most common:

| Variable | Purpose |
|---|---|
| `NVIDIA_API_KEY` / `NVIDIA_NIM_API_KEY` | model API key |
| `POSTGRES_PASSWORD` | database password (change it before first start) |
| `CONSOLE_PORT` | host port of the console (default 8501) |
| `CHAT_MODEL` | chat model, if the default is unavailable to your account |
| `WEALTHPILOT_DEMO` | `1` to enable demonstration mode |

The complete list is in [Configuration](configuration.md).

## Demonstration mode

Demonstration mode adds a **Try a sample applicant** tab to the New case page, so the system can be tried without real documents. It needs demonstration data: 80 sample applicants with statements in
three layouts, and the mock news and registry sources. The data is generated by the research tooling into the `data` volume:

```bash
make demo-data                                  # runs the generator in the lab container (several minutes)
WEALTHPILOT_DEMO=1 docker compose up -d         # restart the services with demonstration mode on
```

Without demonstration mode the console shows only the real application form, and the adverse-media and registry checks return no results because their bundled providers are mocks (see
[Known limitations](../administration/limitations.md)).

## Update, stop and reset

```bash
git pull && docker compose up -d --build        # update
docker compose down                             # stop, keeping all data
docker compose down -v                          # stop and DELETE all data
```

See [Operations](../administration/operations.md) for backups, health monitoring and housekeeping.

## Local installation without containers

For development, the application can run directly on the host with `uv`; the database still comes from Compose. See the [developer guide](../architecture/development.md).
